Typer of hyperparameters 
    n_estimators 
        Number of boosting rounds (number of trees)
            Potentialy better performance but aslo higher chance of overfitting 
        
    max_depth
        Maximum depth of each tree 
            More complex trees, better fit --> Small number for better generlization (3-7)

    learning_rate (eta)
        Controls how much contribution each iteration/model has 
            Smaller = slower learning, usually more accurate (0.01 - 0.3)

    subsample
        Percentage of training data used per tree (0 - 1)
            lower = more regularization, prevent overfitting (0.6 - 0.9)
        
    colsample_bytree
        Fraction of features used per trees 
            Prevent overfitting, works across features (0.6 - 0.1)

    gamma 
        Mimimum loss reduction needed to make further partition to leaf 
            Higher = more conservative 

    min_child_weight
        Minimum sum of instance weights in child 
            Larger = more conservative 
        
    reg_alpha 
        L1 regularization (add sparsity)

    reg_lambda 
        L2 regularization (reduce model comnplexity)

hyperparameter tuning methods:

    GridSearchCV
        * Tries every possible combination of hyperparameters in the specified grid 
        * Exhuastive and guarenteed to find the best combination within the grid 
        * VERY SLOW --> Use for small grids 
    
    RandomSearchCV
        * Randomly samples from hyperparameter space a fixed number of times 
        * Faster and more efficient for large search spaces 
        * Might miss the best combination but usually gets closs
        * number of combinations to try = n_iter
